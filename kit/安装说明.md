# 项目主管技能包 · 安装说明（给朋友）

这是一套 DSH（DeepSeek Harness）的「项目主管」扩展：让一个会话变成项目中枢——拆解目标、在共享任务板登记工作项、用 Agent Teams 在工作区里并行开多个对话框执行、验收产物并汇报。纯文本、无网络请求、可自由复制修改。

## 前置条件

1. 你的机器上已经能运行 DSH（例如 `dsh web` 能打开界面；`dsh --version` 有输出）。
2. 有 Node.js ≥ 18（Windows / macOS / Linux 都只需 Node，**不需要 bash 或 python**；Windows 用 `node install-supervisor.mjs` 即可）。macOS / Linux 也可用 bash 脚本，二选一。
3. 本包按 DSH 0.2.x 的技能与 Agent Teams 语义编写；更高版本应向后兼容。

## 方式一：全套安装（推荐）

> 包内文件名是 UTF-8 中文：Windows 若解压出乱码，请用 7-Zip 打开（或 `tar -xf`），不要用老旧解压工具。分享包已做过轻量化（截图压缩为 JPEG），约 0.4MB。

```bash
# 1) 解压后进入目录
cd project-supervisor-kit

# 2) 装到你的项目工作区（把 /path/to/your-project 换成实际目录）
bash install-supervisor.sh /path/to/your-project

# 可选：同时带上调研资料与决策模板
bash install-supervisor.sh /path/to/your-project --with-research

# 可选：装成全局技能（之后任意工作区说「你当项目主管」都能用）
bash install-supervisor.sh /path/to/your-project --global-skill
```

**Windows（无需 bash，PowerShell / CMD 都行）：** 在解压后的包目录里：

```bat
node install-supervisor.mjs C:\path\to\your-project
node install-supervisor.mjs C:\path\to\your-project --with-research
node install-supervisor.mjs C:\path\to\your-project --global-skill
```

macOS / Linux 也可以用 `node install-supervisor.mjs`，与 bash 脚本等价。

脚本会写入三样东西（已有 `AGENTS.md` 时不覆盖，会生成 `AGENTS.supervisor.md` 供你合并）：

- `AGENTS.md`：项目主管常驻规则，该工作区**每个新会话自动注入**，自动进入主管模式
- `.dsh/skills/project-supervisor/`：主管技能目录（`SKILL.md` + `templates/` 四个工作流模板：plan / task-brief / ledger / review-gate；含 14 条硬化规则与七步流程：立项→拆解→任务板→派发→监管→验收→汇报）
- `.dsh/skills/improving-prompts/`：提示词润色技能完整目录（SKILL.md + LICENSE + references + templates）
- `主管手册.md`：使用说明、限制、冒烟清单
- （可选）`patches/team-permissions/`：给对话框指定权限范围的补丁工具

装完后：在 DSH 里把该目录打开为工作区、**新建会话（cwd 必须是该目录）**，直接说项目目标即可。想看并行对话框，打开会话页头的「智能体团队」面板。

## 方式二：只要技能（最轻，30 秒）

不需要整个包，只把技能文件放到全局技能目录：

```bash
mkdir -p ~/.dsh/skills/project-supervisor ~/.dsh/skills/improving-prompts
cp -R skill/. ~/.dsh/skills/project-supervisor/
cp -R skill-improving-prompts/. ~/.dsh/skills/improving-prompts/
```

之后在任意 DSH 工作区的新会话里说「你当项目主管」「开几个对话框并行做」即可触发（按需加载，不改变其他行为）。如果只想让某个工作区用，把**整个目录**放到 `<工作区>/.dsh/skills/project-supervisor/` 即可（`SKILL.md` 配 `templates/` 四个模板，对应 14 条工作流硬化规则）。

## 方式三：手工复制（不想跑脚本时）

把以下文件按路径拷过去即可：

| 本包文件 | 拷到 |
|---|---|
| `AGENTS.supervisor.md` | `<工作区>/AGENTS.md`（若已有 AGENTS.md，把内容合并进去） |
| `skill/`（整个技能目录：SKILL.md + templates/ 四个模板） | `<工作区>/.dsh/skills/project-supervisor/` |
| `skill-improving-prompts/`（整个目录：SKILL.md + LICENSE + references/ + templates/） | `<工作区>/.dsh/skills/improving-prompts/` |
| `主管手册.md` | `<工作区>/主管手册.md` |
| `research/`（可选） | `<工作区>/research/` |

## 验证是否生效

1. 文件在位：全局或工作区 `.dsh/skills/project-supervisor/` 下应有 `SKILL.md` 与 `templates/`（4 个 .md）
2. 新会话里说「你当项目主管」，回复应体现主管流程（先定完成定义与拆解，而不是直接写代码）；并行时会创建任务板并开启多个对话框。
3. 技能目录出现 `project-supervisor` 条目即加载成功（无需重启 DSH）。
4. （可选）装了 UI 插件后，刷新 DSH 页面，侧栏出现「主管」入口；点开能看到当前工作区的工程底线自检，「零基础保护」卡片右上角有开关（host 半侧需重启 `dsh web` 后才写工作区文件）。

## 常见问题

- **说了没反应**：确认会话 cwd 是装了 `AGENTS.md` 的那个工作区；全局技能只提供流程，不会让会话自动变主管（自动模式靠该工作区的 `AGENTS.md`）。
- **已有 AGENTS.md**：脚本默认不覆盖，会生成 `AGENTS.supervisor.md`；手工合并或加 `--force` 覆盖。
- **多智能体 token 成本**：默认只在任务确实独立时才并行（约 15× token），简单任务主管会自己做。
- **卸载**：删除 `~/.dsh/skills/project-supervisor` 以及工作区里的 `AGENTS.md` 相关段落即可，无其他副作用。
- **research/ 里的路径**：那是作者机器上的调研记录与 DSH 安装路径，仅作参考，不代表你的机器。
- **想给不同对话框设不同权限**：原生不支持；kit 带可选补丁 `patches/team-permissions`（需要 python3 + node，应用后重启 DSH 生效，可一条命令回滚），详见该目录 README。补丁 v2 另支持 `tools: "read-only"` 收窄工具可见性（不能写文件/跑 bash，但仍能汇报）。
- **想要图形界面**：kit 带可选 DSH Web 插件 `plugin/dsh-project-supervisor/`。macOS/Linux：`cd plugin/dsh-project-supervisor && bash install-plugin.sh`；**Windows**：`cd plugin\dsh-project-supervisor` 然后 `node install-plugin.mjs`。刷新 DSH 页面后侧栏出现「主管」面板（工程底线自检 / 工作流 / 快捷口令）。它只装进 DSH profile、不写你的项目文件，卸载把最后参数换成 `--uninstall`。
- **插件会让 DSH 崩吗**：不会——host 半侧已加固（配置路由注册失败只禁用插件、HTTP handler 任何异常都返回 JSON、响应已断开也不会抛到进程；导入插件无副作用）。真机 Windows 无法在本机复现，但已用 win32 路径语义模拟 + 崩溃安全测试覆盖（见 `plugin/dsh-project-supervisor/scripts/compat-check.mjs`）；朋友按测试指南第 8 节做一次开关/重启验证即可。万一 DSH 起不来：`node install-plugin.mjs --uninstall`，或删掉 profile `package.json` 里的 `dsh-project-supervisor` 后重启。
- **提示词润色是什么**：套件会把 improving-prompts 技能装进工作区；主管默认先用一行「润色要点」把需求工程化再执行，可在 DSH「主管」面板用「提示词润色」滑块关闭（写 `.dsh/supervisor.config.json` 的 `promptPolish`），也可在单次指令里说「这次别润色」。
- **效率优先和严格派发是什么**：DSH「主管」面板最上端的二选一。默认「效率优先」：主管自己做紧耦合小修、把独立工作派给对话框；「严格派发」：所有文件写入都必须由对话框完成，主管只指挥、评审、验收（更慢，但能验证主管不亲自干活）。状态写 `.dsh/supervisor.config.json` 的 `dispatchMode`。
- **维护脚本没随包提供**：`sync-kit.sh` / `build-dist.sh` / `selftest.sh` / `verify-facts.sh` 是给**源工作区**维护者用的，不随分享包分发；你只需要 `install-supervisor.sh` / `install-supervisor.mjs`。
