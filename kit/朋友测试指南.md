# 项目主管套件 · 朋友测试指南

这是一份「拿到包就能照着做」的测试指引：从校验安装包、安装主管、可选装 DSH Web 面板，到逐项测试和卸载。全程约 20–30 分钟。

> 测试请用**一个空的测试目录**，不要拿正在用的项目试。卸载步骤会删除安装文件，测试目录可以整个删掉。

## 0. 开始前

你需要：

- 能运行 DSH 的系统（macOS / Linux / **Windows**）；Windows 不需要 Git Bash/WSL：装 Node.js ≥ 18 后把下面的 `bash install-supervisor.sh` 换成 `node install-supervisor.mjs` 即可（插件安装同理：`node install-plugin.mjs`）。
- 一个空目录，例如 `~/projects/supervisor-test`（下文都用这个路径，换成你自己的即可）。
- 10–30 分钟。
- 先记下环境，出问题时贴给作者：

```bash
dsh --version
node --version
uname -a          # Windows PowerShell 里用：$PSVersionTable
```

Windows 用户请确认 `node --version` 输出 v18 或更高。

## 1. 校验安装包（1 分钟）

你应该拿到两个文件（在 `~/Downloads` 或你保存的位置）：

```text
project-supervisor-kit-2026-10-24.zip
project-supervisor-kit-2026-10-24.zip.sha256
```

在**同一个目录**里校验（本文命令按 `2026-10-24` 的包名写；如果你的包日期不同，把命令里的日期换成实际日期）：

```bash
cd ~/Downloads
shasum -a 256 -c project-supervisor-kit-2026-10-24.zip.sha256
```

期望输出最后是：

```text
project-supervisor-kit-2026-10-24.zip: OK
```

Linux 也可以：

```bash
sha256sum -c project-supervisor-kit-2026-10-24.zip.sha256
```

如果显示 `FAILED` 或文件不存在：重新下载两个文件（`.sha256` 也要重下），不要继续安装。Windows 没有 `shasum` 时，用 PowerShell 算：

```powershell
Get-FileHash .\project-supervisor-kit-2026-10-24.zip -Algorithm SHA256
```

把输出和 `.sha256` 文件第一列对比，一致即可。

## 2. 解压并安装主管（3–5 分钟）

```bash
cd ~/Downloads
unzip project-supervisor-kit-2026-10-24.zip
cd project-supervisor-kit-2026-10-24
ls
```

> 包约 0.4MB（417KB，截图已压缩）；文件名为 UTF-8 中文，Windows 若解压乱码请用 7-Zip 或 `tar -xf`。

应能看到 `install-supervisor.sh`、`AGENTS.supervisor.md`、`主管手册.md`、`skill/`、`skill-improving-prompts/`、`THIRD_PARTY_NOTICES.md`、`朋友测试指南.md`。

建测试目录并安装（macOS / Linux）：

```bash
mkdir -p ~/projects/supervisor-test
bash install-supervisor.sh ~/projects/supervisor-test
```

**Windows（PowerShell，无需 bash）：**

```powershell
mkdir "$HOME\projects\supervisor-test" -Force
node install-supervisor.mjs "$HOME\projects\supervisor-test"
```

可选参数（按需加，不要重复加）：

```bash
# 同时带上调研资料与 DECISIONS 模板
bash install-supervisor.sh ~/projects/supervisor-test --with-research

# 另装全局技能：之后任意工作区都能说「你当项目主管」
bash install-supervisor.sh ~/projects/supervisor-test --global-skill
```

说明：

- 脚本会写入：`AGENTS.md`（常驻规则）、`.dsh/skills/project-supervisor/SKILL.md`、`.dsh/skills/improving-prompts/`（含 `SKILL.md` + `LICENSE` + `references/` + `templates/`）、`主管手册.md`、`patches/team-permissions/`。
- 目标目录已有 `AGENTS.md` 且不含「项目主管」时，不改你的文件，而是生成 `AGENTS.supervisor.md`，需要你手工合并（或加 `--force` 覆盖）。
- `--global-skill` 会写 `~/.dsh/skills/project-supervisor/` 和 `~/.dsh/skills/improving-prompts/`。如果你之前改过这两个目录，先自己备份；安装脚本不自动备份（`sync-kit.sh --global` 才会逐文件备份）。

安装后核对（应全部输出 `OK`）：

```bash
cd ~/projects/supervisor-test
test -f AGENTS.md && echo "AGENTS.md OK"
test -f .dsh/skills/project-supervisor/SKILL.md && echo "主管技能 OK"
test -f .dsh/skills/improving-prompts/SKILL.md && echo "润色技能 OK"
test -f .dsh/skills/improving-prompts/LICENSE && echo "技能 LICENSE OK"
test -f .dsh/skills/improving-prompts/references/diagnosis.md && echo "references OK"
test -f .dsh/skills/improving-prompts/templates/prompt-skeleton.md && echo "templates OK"
test -f 主管手册.md && echo "主管手册 OK"
```

然后在 DSH 里把 `~/projects/supervisor-test` 打开/注册为工作区，**新建会话（cwd 必须是这个目录）**，说：

> 你当项目主管

回复应体现主管流程（先定完成定义与拆解，而不是直接写代码）。

## 3. 可选：安装 DSH Web「主管」面板（3 分钟）

如果你用的是 DSH Web，可以加装侧栏面板（只读看板 + 两个开关）：

```bash
cd ~/Downloads/project-supervisor-kit-2026-10-24
bash plugin/dsh-project-supervisor/install-plugin.sh
```

看到「安装完成」后：

1. **重启 DSH**（在运行 `dsh web` 的终端按 `Ctrl+C`，再执行 `dsh web`）。面板的 host 半侧在 DSH 启动时加载；不重启的话，开关只会先存浏览器 `localStorage`，并提示「重启 DSH 后同步到工作区」。
2. 刷新页面，左侧栏应出现「主管」入口。
3. 点开面板，应看到：项目选择、工程底线自检（`x / 9`）、主管四步工作流、「零基础保护」「提示词润色」「新项目需求追问」三张卡片（右上角各有一个滑块）。

卸载面板（随时可做）：

```bash
cd ~/Downloads/project-supervisor-kit-2026-10-24
bash plugin/dsh-project-supervisor/install-plugin.sh --uninstall
```

然后重启或刷新 DSH。

> 面板除两个开关外只读：不会替你执行 `git init`、写 README 或开对话框；这些仍由对话里的主管完成。

### A. 零基础保护（必测）

**准备**：新建一个空测试目录；确认工作区里没有 `.dsh/supervisor.config.json`，或其中 `beginnerGuard` 不是 `false`。

**输入**（原话发给主管，不要补充技术细节）：

> 帮我做个待办清单网页

**观察**（至少命中 4 项；完整规则见 `主管手册.md`「给零基础用户」和 `.dsh/skills/project-supervisor/SKILL.md` 同名章节）：

- [ ] 先给**最小可运行目标（MVP）**和可执行的完成定义 / 3 条验收标准；
- [ ] 新项目先 `git init`，配置 `user.name` / `user.email`，并至少完成 1 次提交；
- [ ] 写 `README.md`（目标、启动/打开方式、验收）和 `.gitignore`（`node_modules/`、`.env`、`dist/`、`*.log`、`.DS_Store`）；
- [ ] 选「最简单能跑」的方案（例如单文件 `index.html`），并用一句话说明取舍；
- [ ] 告诉你「怎么打开、怎么验收」，而不是只丢一堆代码；
- [ ] 如果涉及密钥：密钥不进代码/git/聊天，只给 `.env.example` 占位（本任务通常不涉及）。

**验收命令**：

```bash
cd ~/projects/supervisor-test
git log --oneline
git status --short
cat .gitignore
sed -n '1,40p' README.md
```

**算通过**：git 有提交、README 与 .gitignore 存在且内容对得上、给出了可执行的打开/验收方式。只写代码、没有安全网 → 记为不通过，附 `git log` 输出或截图。

### B. 提示词润色（必测）

**输入**（故意给一条很粗的指令）：

> 做个网站

**观察**：

- [ ] 先给一行「润色要点」（目标场景 + 补全了哪些缺口 + 用了什么技巧），不写长篇报告；
- [ ] 明确或写死关键假设（做什么站、给谁看、验收标准），缺的事实留 `{{占位符}}` 而不是编造；
- [ ] 同一轮**立即执行**，不是只回一段提示词让你自己去做；
- [ ] 产物仍是能跑的最小版本，不因为润色拖长交付。

**算通过**：能看到「润色要点」→ 增强后的任务 → 实际产物这条链路。若只输出提示词不动手，或反过来完全不说明就乱做，记为不通过。

### B2. 新项目需求追问（必测）

**准备**：新建一个空测试目录（或删掉测试目录里的 `README.md` / `DECISIONS.md` / `.git`，让主管判断为「新项目」）；确认面板「新项目需求追问」开关是开，或 `.dsh/supervisor.config.json` 里 `requirementInterview` 不是 `false`。

> 注意：装套件时 `AGENTS.md` 是套件文件，**不能**当作「旧项目」证据；判断看项目自身的 README/DECISIONS/源码/.git。

**输入**（原话，不要补充细节）：

> 我想做个记账小工具

**观察**（至少命中 3 项）：

- [ ] 不直接开工，先追问关键需求（谁用 / 解决什么 / 核心场景 / 形态 / 数据 / 怎么算做完），一次 3–5 个问题；
- [ ] 每个问题带默认答案，你可以只回「用默认」或「够了，直接做」；
- [ ] 最多 3 批；你喊停后立即停止追问，先给一页纸摘要（目标 / MVP / 验收 / 假设）；
- [ ] 摘要写进项目 `README.md` 与 `DECISIONS.md`，然后才开工；
- [ ] 同一会话里继续让主管改个小 bug（非新项目）时，不再追问。

**算通过**：能观察到「先追问 → 你说停就停 → 写盘 → 开工」这条链路，且继续旧项目不重复追问。

**补充验证（关闭后）**：把面板「新项目需求追问」关掉、重启 DSH 后新建会话，同样说「我想做个记账小工具」，应不再主动追问（但你说「先问清需求」时可以临时执行）。

### B3. 主管工作模式（建议测）

**准备**：打开「主管」面板，确认页面**最上端**有「主管工作模式」卡片，默认选中「效率优先」。

**观察**：

- [ ] 两个选项（效率优先 / 严格派发）有简短说明，点击后选中态立即切换、有 toast；
- [ ] 点「严格派发」后刷新页面，仍是严格派发；切回「效率优先」也保持；
- [ ] 检查 `.dsh/supervisor.config.json` 里有 `"dispatchMode": "strict"`（需 host 半侧已生效；没重启 DSH 时以面板提示为准）。

**再测行为（可选）**：严格派发模式下让主管做一个小改动（例如「把 README 里的项目名改成 Test」）。预期：主管不自己写文件，而是先开一个对话框派任务、再验收结果——这正是两种模式的区别。切回效率优先后，小改由主管直接做。

**算通过**：模式选择在页面最上端、切换可持久化；行为差异可观察到（或主管说明为什么无法派发）。

### C. 三个开关关闭后的行为变化（必测）

1. 打开「主管」面板，把「零基础保护」「提示词润色」「新项目需求追问」三个滑块都关掉。
2. 确认开关写进了工作区（需要装过插件并重启过 DSH）：

```bash
cat ~/projects/supervisor-test/.dsh/supervisor.config.json
```

期望能看到类似：

```json
{ "beginnerGuard": false, "promptPolish": false, "requirementInterview": false, "dispatchMode": "efficiency", "updatedAt": "...", "source": "dsh-project-supervisor" }
```

如果文件不存在：先重启 `dsh web`、刷新页面再点一次开关；点完面板若提示「重启 DSH 后同步到工作区」，按提示重启。然后重新检查文件。

3. **新建会话**（cwd 仍是测试目录），重复 A、B 的输入，观察变化：

- A（零基础保护关闭）：不再主动做 MVP 解释、架构建议、备份提醒、说人话引导；但安全默认仍在——密钥不进代码、删除/发布/推送/花钱要逐条确认、每步先跑通、验收仍要做。
- B（提示词润色关闭）：直接按原话执行（可以写明关键假设），不再先给「润色要点」。
- B2（新项目需求追问关闭）：说「我想做个 X」时不再先追问需求，直接按零基础保护给默认方案开工。

4. 把三个滑块重新打开，新建会话再试一次，行为应恢复。测试结束建议保持三个开关为开。若想回到默认，先确认面板里三个滑块都是开，再删 `.dsh/supervisor.config.json`（否则浏览器里残留的关闭状态可能在下次启动时又写回文件）。

**算通过**：开关状态能在文件里读到，且关/开后的行为差异可观察。只改浏览器状态、文件没变 → 记录「host 半侧未生效」并附重启步骤。

### D. 并行与任务板（建议测）

在一个主管会话里下发两个**互不依赖**的小任务：

> 并行做两个互不依赖的小任务，分别开对话框：
> 1) 在 `docs/a.md` 写 5 条 DSH 使用技巧；
> 2) 在 `docs/b.md` 写 5 条 Git 常用命令。
> 两个任务写范围不重叠，完成后汇总并给验收证据。

**观察**：

- [ ] 任务板出现至少 2 个工作项，写范围互不重叠；
- [ ] 开了 2 个对话框（会话页头「智能体团队」面板可见成员与任务状态）；
- [ ] 产物 `docs/a.md`、`docs/b.md` 存在且内容符合要求；
- [ ] 汇总里附了验证命令/输出，而不是只说「已完成」。

**验收命令**：

```bash
cd ~/projects/supervisor-test
ls docs
sed -n '1,20p' docs/a.md
sed -n '1,20p' docs/b.md
```

**算通过**：两个独立产物 + 任务板/成员可见 + 汇总有证据。注意多智能体 token 约为单会话的 15 倍；如果主管判断任务太小而不并行，记录它的理由即可（不算失败）。

## 5. 通过标准

- **最低通过**：A、B、C 三项通过，安装与卸载各走通一次。
- **完整通过**：A–D 全部通过（D 若主管给出合理的不并行理由，可记「通过（未并行）」）。
- E 不是测试项，是出问题时的反馈格式。
- 有一项不通过也请提交：附上 E 模板和证据，比「感觉不对」有用得多。

## 6. 已知限制

- 套件按 DSH 0.2.x 的工具体系编写；DSH Web 插件针对 0.2.0-rc.2 的 slot/remote 实测，其他版本可能有差异。
- 全局技能（`--global-skill`）只提供流程，不会让任意会话自动变主管；自动进入主管模式靠目标工作区的 `AGENTS.md`。
- 「主管」面板除两个开关外只读：不执行 git、不写 README、不开对话框；这些由对话里的主管完成。
- 面板开关写入需要 host 半侧已加载（装/改插件后重启 `dsh web`）；重启前只存浏览器 `localStorage`。
- 面板的项目列表来自会话记录的 `cwd`：新工作区要先在 DSH 里打开并新建会话，才会出现在面板里。
- 并行会显著增加 token 消耗（约单会话 15 倍）；简单任务主管通常不并行，这是预期行为。
- Windows 原生 CMD/PowerShell 不能直接跑 bash 脚本；请用 Git Bash/WSL，或按 `安装说明.md` 方式三手工复制。
- `install-supervisor.sh --global-skill` 会覆盖同名全局技能文件，不自动备份；改过全局技能的话先备份。
- 卸载是手工删除安装文件；`.bak.<时间戳>` 备份、你自己的项目文件不会被自动清理。
- 包内 `research/` 是作者的调研记录，可能含作者机器的环境描述，仅作参考，不代表你的环境。
- 本套件安装与技能加载不发起网络请求；`references/sources.md` 里的链接只是文字引用。

## 7. 卸载

### 7.1 卸载 DSH Web 面板

```bash
cd ~/Downloads/project-supervisor-kit-2026-10-24
bash plugin/dsh-project-supervisor/install-plugin.sh --uninstall
```

然后重启或刷新 DSH，侧栏「主管」入口消失。

### 7.2 删除工作区里的安装文件

**只对测试目录做这一步。** 如果这个目录原本就有你自己的 `AGENTS.md`，不要直接删，改为手工移除其中的主管段落。

```bash
cd ~/projects/supervisor-test

# 先看一眼要删什么
ls -la
ls .dsh/skills

# 删除套件安装的技能、补丁、面板配置
rm -rf .dsh/skills/project-supervisor
rm -rf .dsh/skills/improving-prompts
rm -rf patches
rm -f .dsh/supervisor.config.json

# 删除套件写入的文档/规则（原有文件请先备份再决定）
rm -f AGENTS.md AGENTS.supervisor.md 主管手册.md

# 只有安装时用了 --with-research 才删
rm -rf research
```

如果测试目录里还有你让主管生成的项目文件（`README.md`、`index.html`、`.git` 等），确认不要了再整个删：

```bash
cd ~
rm -rf ~/projects/supervisor-test
```

### 7.3 删除全局技能（只有用了 `--global-skill` 才需要）

```bash
ls ~/.dsh/skills
rm -rf ~/.dsh/skills/project-supervisor
rm -rf ~/.dsh/skills/improving-prompts
```

删之前确认这两个目录不是你自己原有的；全局目录里可能还有安装时留下的 `.bak.<时间戳>` 备份，可一并清理。

### 7.4 删除安装包

```bash
cd ~/Downloads
rm -rf project-supervisor-kit-2026-10-24
```

## 8. Windows 兼容性专项（华为/普通 Windows 笔记本）

如果你用的是 Windows，请额外按本节验证（约 5 分钟）：

1. **环境**：`node --version` ≥ v18；`dsh web` 能正常打开。
2. **安装**：`node install-supervisor.mjs <测试目录>`；可选插件 `cd plugin\dsh-project-supervisor` + `node install-plugin.mjs`。
3. **面板**：刷新 DSH 页面 → 侧栏「主管」→ 切换三个开关（零基础保护 / 提示词润色 / 新项目需求追问）；确认没有白屏、没有报错弹窗。
4. **落盘**：在测试目录里应能看到 `.dsh\supervisor.config.json`（只有存在过会话记录的工作区才能从面板写入；没有就新建一个会话再点开关）。
5. **重启**：关掉 `dsh web` 再重新启动，页面能正常打开、面板还能用——这一步专门验证「插件不会让 DSH 进程起不来」。
6. **崩溃恢复**（万一第 5 步失败）：先执行 `node install-plugin.mjs --uninstall`，再重启 `dsh web`；仍失败就把 `%USERPROFILE%\.dsh\profiles\web\package.json` 里的 `dsh-project-supervisor` 两处（dependencies 与 dsh.profile.bundles）删掉。把报错原文贴给作者。

> 说明：作者本机是 macOS，已用 win32 路径语义模拟 + 防御式 host 代码 + 双平台 Node 脚本做过自动化测试（`compat-check` 32 项 PASS），但没有真机 Windows 硬件；所以本节第 5 步是**唯一必须人工确认**的一项。
