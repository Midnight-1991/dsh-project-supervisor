# 一键安装口令（复制到任意新工作区的新会话里）

把下面整段**复制**，粘贴到任意 DSH 工作区的新会话里。agent 会自己从 GitHub 下载主管套件、装进当前工作区并逐项验收；装完你再**在同一目录新建一个会话**，常驻规则就生效了。

```text
请把「项目主管套件」一键装到当前工作区（cwd 即目标），不要改已有文件、不要 git commit/push。
1) 下载套件（任选其一，失败换下一个）：
   仓库路线：git clone --depth 1 https://github.com/Midnight-1991/dsh-project-supervisor.git /tmp/dsh-project-supervisor-kit && bash /tmp/dsh-project-supervisor-kit/kit/install-supervisor.sh . --with-research --with-setup
   zip 路线（无 git）：从 https://github.com/Midnight-1991/dsh-project-supervisor/releases 下载 project-supervisor-kit-*.zip，解压后运行 bash <解压目录>/install-supervisor.sh . --with-research --with-setup
   Windows：把上面脚本换成 node <目录>\install-supervisor.mjs . --with-research --with-setup
2) 验收并逐项告诉我：AGENTS.md 是否以「# 项目主管作业规则（本工作区）」开头；.dsh/skills/project-supervisor/SKILL.md 与 templates/ 五个模板；主管手册.md；research/README.md 与 research/DECISIONS.md；setup/ 下是否有 sync-kit.sh、selftest.sh、verify-facts.sh、build-dist.sh、一键安装口令.md；.dsh/supervisor-kit.json 的版本号与 withResearch/withSetup 字段。
3) 装完提醒我在同一目录「新建会话」让常驻规则生效；本会话先按 AGENTS.md 规则继续。
4) 失败就原样贴出错误与退出码，不要擅自删文件重试。
```

## 为什么这样能“一键”

- 套件的安装器 (`install-supervisor.sh` / `.mjs`) 是幂等的：默认只补缺失文件，不改已有文件、不覆盖 AGENTS.md，并在 `.dsh/supervisor-kit.json` 写安装记录（含 `withResearch` / `withSetup`）。
- 它装的不只是 `AGENTS.md`，还有项目级技能（含 14 条工作流硬化与五个模板）和提示词润色技能；所以装完新会话即具备完整主管行为。

## 装进去的 `research/` 和 `setup/` 是什么

- `research/`：调研与决策资料（`README.md` 总览 + 分报告 + `DECISIONS.md` 模板）。新会话开工时按规则会先读 README/DECISIONS，避免重复造轮子和丢上下文。
- `setup/`：工程化脚本（`sync-kit.sh` 同步、`selftest.sh` 回归、`verify-facts.sh` 事实核验、`build-dist.sh` 打包，以及安装器与文档模板）。当项目也按「主管套件」维护时可以重跑自检；普通项目不用管，不影响主管行为。
- 不想要这两个目录：把命令里的 `--with-research --with-setup` 去掉即可（最小安装）。

## 也可以不用口令

- 本机已有套件：`bash <源工作区>/setup/install-supervisor.sh /path/to/ws --with-research --with-setup`
- 分享包：解压后 `bash install-supervisor.sh /path/to/ws`；Windows 用 `node install-supervisor.mjs C:\path\to\ws`
- 详细说明见同目录 `安装说明.md` 与 `主管手册.md`。
