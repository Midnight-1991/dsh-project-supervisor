> 用法：每个任务一份，作为派发命令的必带附件；实现者与独立评审共用。可内联进 spawn 命令，但必须落文件。

- 任务 id / 名称：
- 计划引用：<plan.md 路径 + 任务行号>
- 模型：<默认 或 provider/model/effort；跨模型仅 subagent，派发前用 list_subagent_models 校验；评审须与实现不同模型>
- 前置基线：`git status` 干净，或已记录基线（附 `git status --porcelain` 输出）
- 权限：继承创建时固定（审批 never）；越权上报不重试；需要更大权限先停下请用户调整
- 当前状态：planned / in_progress

## 约束

- 技术 / 风格：
- **唯一允许写入**：<路径，互不重叠；越界写入视为失败>
- 禁止：<不要改哪些文件、不要编造、不要跑哪些命令、不运行 git 等>

## 验收标准

- [ ] <可执行命令 / 检查 + 预期结果（退出码 0、输出含 X、页面能打开…）>
- [ ] <…>
- 验收证据：命令 + 关键输出 + 退出码 + diff 位置

## 交付

- 产出文件：
- report 格式：做了什么 / 验证命令与输出 / 存疑项（≤200 字摘要 + 证据路径）
- 完成后：按 Gate 自测 → 标记 complete → 回复 report；等独立评审，blocking 清零才算完成

## 边界与风险

- 不确定处先问主管，不自行扩大范围
- 不可逆动作（删除 / 发布 / 推送 / 花钱）先停下上报
- bug 类任务：先复现 + 根因一句话，再动手改

## 评审关注点（交给评审者，禁止 pre-judge）

- spec 符合度：逐条对照上面验收标准
- 质量：正确性 / 回归风险 / 可维护性 / 安全
- 不要告诉评审「这个不用报」「大概看看就行」
