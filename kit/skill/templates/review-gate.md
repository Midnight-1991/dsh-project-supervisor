# 评审门禁（review-gate.md）

> 用法：独立评审者（只读）按本模板出结论；实现者不得自评。评审输入三件套：**brief + report + diff**。
> 禁止 pre-judge：主管/实现者不得对评审说「这个不用报」「大概看看就行」。

## 输入

- task-brief：<路径>
- 评审模型：<与实现不同的模型（可用时）；同模型请标注「非跨模型」>
- 实现 report：<路径或对话摘要>
- diff：`git diff <base>..<head>` / 文件清单
- 验收命令与输出：<贴出命令 + 关键输出 + 退出码>

## 双结论（缺一不可）

### 结论 1：spec 符合度

| brief 验收项 | 是否满足 | 证据（命令 / 输出 / 文件行号） |
|---|---|---|
|  | 满足 / 不满足 / 部分 |  |

### 结论 2：质量结论

- **overall**：通过 / 有条件通过 / 不通过
- **blocking**（必须修，逐条编号）：<问题 + 文件:行号 + 为什么必须修>
- **advisory**（可记录不修）：<问题 + 建议>
- **evidence**：测试输出、diff 关键行、文件路径

## Gate 五步（声明完成前逐条打勾，缺一不可）

- [ ] 1. 认定完成项：对照 brief 每条验收标准
- [ ] 2. 找到验证命令：测试 / 构建 / lint / 手工步骤明确可执行
- [ ] 3. 完整跑一遍：不跳用例、不 partial、用新结果
- [ ] 4. 读输出与退出码：退出码 0 且输出符合预期
- [ ] 5. 证据入 report：命令 + 关键输出 + 退出码 + diff

## 失败表（出现任一即驳回重验）

| 失败情形 | 处理 |
|---|---|
| 没跑测试 / 构建就声明完成 | 驳回，跑完再报 |
| 只跑部分用例或跳用例 | 补全量；做不到则说明原因并请用户确认 |
| 只有结论没有输出 / 退出码 | 补证据 |
| 退出码非 0 写成通过 | 驳回，修到通过 |
| 用旧输出冒充新结果 | 重跑 |
| 越界写入未说明 | 驳回 + 记录账本 |
| 说「应该没问题」 | 不符合 Gate，重验 |

## 红旗词（听到 / 说出即停，按 Gate 重验）

should / probably / seems / 应该没问题 / 基本完成 / 测试应该能过 / 小改动不用测 / 我记得没影响 / 先上线再补测试

## 评审纪律

- 只读，不替实现者改代码
- 不接受 pre-judge；每条 blocking 必须可定位（文件:行号）且可验证
- 有界：修复后只做 **scoped re-review**（只看 blocking 项 + 新 diff）；同一任务最多 2 轮，之后升级裁决（换个评审 / 主管裁决 / 交还用户）
- 结论与裁决写进 `LEDGER.md`
