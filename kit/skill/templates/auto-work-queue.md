# 自动工作队列（auto-work-queue.md）

> 用途：`autoWork:true` 时的无人值守待办与日志。复制到工作区根 `.dsh/auto-work-queue.md` 使用。
> 规则：五个二级节固定、顺序不变；条目一律以 `- ` 开头；空节写 `- （空）`；只由主管写。
> 开关：`.dsh/supervisor.config.json` 的 `"autoWork"`（默认 `false`，不改变常规行为）与 `"economicalAutoWork"`（默认 `false`，开启后按 DeepSeek 峰谷价暂停/恢复，见 AGENTS/SKILL「经济模式」）。
> 每 tick 先读本文件，再读任务板与在跑对话框；收尾时写最终日志并给用户总结。

## 排队任务

> 格式：`- [ ] <目标一句话>｜写范围：<路径>｜验收：<命令/检查>｜依赖：<task id 或无>`
> 示例：`- [ ] 补 README 启动命令｜写范围：README.md｜验收：命令可照做｜依赖：无`
> 只放可自动推进项；写范围与在跑任务冲突或有 `blocked_by` 依赖的先留这里，等上游完成再派。

- （空）

## 阻塞

> 格式：`- <阻塞事项>｜原因：<不可逆/需授权/缺信息/等上游>｜需要：<谁来做什么>`
> 示例：`- 发布到 npm｜原因：需授权（不可逆/对外）｜需要：用户确认`
> 推送/发布/删除/花钱/改系统配置/对外发送等不可逆需求只记这里，绝不自动执行；被拒动作不重试。

- （空）

## 待回答的问题

> 格式：`- Q：<本该问用户的问题>｜默认假设：<按什么继续>｜备选：<其他选项>`
> 示例：`- Q：Node 版本用 18 还是 20？｜默认假设：兼容 Node ≥18｜备选：固定 20`
> 自动工作期间不弹窗提问：写这里并立即用默认假设继续，收尾总结时集中列出。

- （空）

## 自动工作日志

> 格式：`- [HH:MM] <tick 小结：做了什么/派发了什么/状态变化/为何收尾>`
> 示例：`- [22:10] tick1：读队列，派发 README 任务；无阻塞变化`
> 每 tick 追加一行；收尾追加最终总结（完成 / 阻塞 / 待回答问题）。事件行：`- [HH:MM] [暂停]/[恢复] <边界时刻或恢复点>`。

- （空）

## 经济模式状态

> 仅 `economicalAutoWork:true` 时填写；关闭时写 `- （空）`。格式：每行 `- <字段>：<值>`，九字段固定、顺序不变。
> 字段：状态（运行/已暂停）｜边界（高峰起止，UTC+北京）｜暂停原因｜当前任务与 phase｜最后检查点｜产物路径｜在跑 agent｜下一步｜恢复时间（谷价开始后 1–3 分钟）。
> 示例：`- 状态：已暂停｜原因：进入高峰 06:00–10:00 UTC｜恢复时间：谷价开始后 1–3 分钟首个 tick`
> 暂停前把只存在对话里的中间结论写盘、更新 LEDGER；恢复先核对产物与任务状态（已完成不重派），从中断点续并写 [恢复] 日志。
