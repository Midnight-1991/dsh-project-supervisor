# 任务账本（LEDGER.md）

> 用法：每个项目一份，放项目根或 `docs/`；主管维护，所有对话框可见。
> 作用：上下文压缩 / 换会话 / 多对话框并行之后，靠它恢复「谁做了什么、为什么、裁决是什么」。

## 恢复现场先读

1. 本文件（按时间倒序看最近 10 行）
2. `plan.md` 任务表状态
3. `team_task_list` / 任务板状态
4. 最近 3 个 commit（`git log --oneline -3`）

## 事件类型与写法

- **完成**：task id + 产出路径 + 验收证据摘要（命令 / 退出码 / 测试数）
- **决定**：决定内容 + 一句话理由 + 影响范围（选型、范围变更、优先级）
- **裁决**：blocking / advisory 判定 + 理由 + 谁裁的（主管 / 用户）
- **阻塞**：卡在什么 + 已试过什么 + 需要谁解决
- **重派 / 升级**：原 owner 失败原因 + 新 owner / 换方案 / 交还用户
- **模型**：实现/评审实际使用的 provider/model/effort（或「默认」），便于 A/B 与成本复盘
- 一行一件事，不写流水账；裁决必须写理由，不写「显然」。

## 与其它来源对账

- DSH 任务板：状态与 owner（claim / complete）
- `DECISIONS.md`：重要架构 / 范围决策的详细版
- commit：每个任务一个 commit（消息含 task id）
