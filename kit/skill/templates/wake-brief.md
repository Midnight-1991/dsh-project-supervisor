# 唤醒简报（warm-start brief）

> 用途：唤醒 inactive 团队成员时先发这份简报。收到「对齐摘要」并经主管确认后再派活，避免陈旧上下文。

## 1) 项目现状（必填）
- HEAD：<commit>（最近提交：<一句话>）
- 规则版本：<AGENTS.md / SKILL.md 有哪些新变化；预算/开关有无变化>
- 关键文件：<plan.md / DECISIONS 最近条目 / 本次涉及的路径>

## 2) 本次任务
- 角色：<沿用你之前的能力范围：…>
- 任务：<一句话>
- 唯一允许写入：<路径>（越界写入视为失败）
- 验收：<可执行检查 + 命令>
- 交付：<report（做了什么/验证命令与输出/存疑项）+ diff>

## 3) 对齐要求（先对齐、后动手）
- 先读：<AGENTS.md / SKILL.md / 指定文件>
- 先回复一段 ≤120 字「对齐摘要」：你记得的项目状态、本次任务边界、你打算第一步做什么；我确认后再执行。
- 若发现规则或文件已变化，先指出差异再继续，不要按旧记忆动手。

## 4) 边界
- 不重发旧消息、不自行新建成员；失败原样报错，不删文件重试。
- 完成后按流程 claim/complete 并回 report；不要给自己签收。
